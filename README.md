# Codex Watchdog / Codex 守望铃

一个独立的 Windows 桌面提醒工具：用小悬浮球显示本机 Codex 聊天的状态，在需要回答、授权或一轮工作结束时播放铃声。

这是社区项目，与 OpenAI 无隶属、赞助或官方支持关系。它依赖 Codex 桌面端当前的本地运行记录格式，不承诺兼容所有版本。

## 下载与运行

1. 从 [Releases](https://github.com/langhua821/codex-watchdog/releases) 下载 Windows x64 发布 ZIP，并完整解压到一个准备长期保留的文件夹。
2. 保留 `CodexWatchdog.exe` 旁的整个 `sounds` 文件夹，再双击 EXE。不要直接在 ZIP 预览中运行。
3. 在 Windows 右下角系统托盘中找到守望铃图标，点击打开设置。图标可能在“隐藏的图标”中。
4. 在“监控聊天”中勾选希望提醒的聊天，并选择铃声、音量。设置自动保存。

发布包不需要安装 Python、开发用 .NET SDK 或另一个 AI。运行环境是 Windows x64 和 .NET Framework 4.x，音频播放使用 Windows 的媒体能力。暂不支持 macOS、Linux 或浏览器版聊天。

目前发布的 EXE **未进行代码签名**。Windows 可能显示未知发布者或 SmartScreen 提示；请核对下载来源，不要为了运行本程序关闭系统安全保护。也可以从源码自行构建。

## 如何使用

- **悬浮球**：约 72×72 逻辑像素，可拖动。响铃时单击确认停铃；平时单击暂停或继续。球本身不占任务栏窗口。
- **多选聊天**：只有勾选范围会提醒。可以选择“全部聊天（包括后台巡查）”，也可以逐个选择；全不选即不监控。取消勾选会撤销该聊天的待提醒。具体选择模式不会自动加入新发现的聊天，已勾选但暂不可用的选择会保留。
- **新问题立即提醒**：已选聊天出现新的结构化问题或授权请求时提醒，包括仍在工作的异步提问。读取到回答后会撤销对应提醒；也可手动确认或稍后提醒。初次接手的旧问题不会补响。
- **结束后确认停稳**：观察到工作转为完成、中断或停止异常后，需要至少 4 秒后的新鲜记录确认才提醒。短暂停顿后自动续跑会取消候选；重新工作会撤销旧结束提醒。这个时间不是精确的 4 秒倒计时，还取决于轮询和记录是否完整。
- **三类铃声**：待回答/授权、结束/中断、停止异常分别选择，音量共用。内置 21 首音乐，也支持本地 WAV/MP3 和最多 8 秒试听。自选文件按原路径引用，请保留原文件。
- **稍后提醒与退出**：右键悬浮球或托盘图标可选择稍后提醒、暂停、显示/隐藏和退出。关闭设置窗口仍会继续监控。

“显示无活动状态”只改变球上的状态，不会因为长时间没有新记录而响铃。长时间思考、远程等待和工具执行也可能暂时没有记录。

## 自启动与应用跟随

“登录 Windows 时自动启动”和“仅在 Codex / ChatGPT 运行时显示悬浮球”默认开启。首次运行后，程序为当前 Windows 用户登记自己的启动项，不需要管理员权限。

要关闭自启动，请从托盘打开设置，在“启动与显示”中取消“登录 Windows 时自动启动”。随后可从托盘退出程序，再移动或删除文件夹。不要只删除 EXE 而留下失效的启动路径。

聊天应用完全退出时，守望铃隐藏球、停止自动提醒并在托盘待命；应用重新打开后建立新基线。应用在后台或最小化时仍算运行。应用未运行时仍可在设置中主动试听。程序不会自动跟随当前点击的聊天页面。

## 工作原理与限制

守望铃只读本机 `%USERPROFILE%\.codex\sessions` 下的运行记录和会话名称索引，不读取屏幕，不调用 AI，不向聊天应用发送消息，也不修改聊天记录或账户数据库。

程序通常每 2 秒读取变化，每 10 秒发现聊天；当前发现范围最多为最近 128 个桌面主聊天，排除已识别的子代理记录。最近恢复使用的旧聊天也可以被发现。选择“全部”仍受这个发现范围限制。

它判断的是本地记录中的状态变化，不能可靠推断未写入记录的云端任务，也不能把一轮结束当成整个项目完成。普通自然语言提问不一定有独立请求事件；没有结构化请求时，可能只在本轮结束后提醒。被勾选的自动巡查聊天也按这些规则提醒。

未知格式、读取失败、记录尚未追赶完成时，不会直接认定工作已经结束。电脑休眠、应用退出、音频设备/解码器问题以及桌面端更新都可能影响提醒。更新桌面端后若出现误报或漏报，请提交脱敏的问题报告。

## 本地数据与隐私

守望铃本身不上传聊天或诊断记录，也不另存聊天正文、工具参数。它会在当前用户的本地应用数据目录保存：

| 文件 | 内容 |
|---|---|
| `%LOCALAPPDATA%\CodexWatchdog\settings.json` | 监控选择、铃声文件路径、音量和窗口位置等设置 |
| `%LOCALAPPDATA%\CodexWatchdog\monitor-events.jsonl` | 程序版本、时间、操作、提醒类型、聊天标题/ID及轮次/事件标识 |

诊断日志约 512 KiB 后轮换，保留当前文件和上一份 `.previous`。**聊天标题、ID和本地音频路径仍可能属于私人信息**，不要未经检查就上传设置或日志全文。提交问题时只提供必要片段，并移除个人信息。退出程序后可删除日志；再次运行会按需重新生成。

## 从源码构建

使用 Windows PowerShell，在仓库根目录执行：

```powershell
git clone https://github.com/langhua821/codex-watchdog.git
cd codex-watchdog
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

构建脚本调用系统 .NET Framework 编译器，输出位于 `dist`。运行时同样需要保留 `dist\sounds`。若系统缺少脚本指定的编译器或 WPF 组件，脚本会报错；请先准备相应的 .NET Framework 环境。

运行构建与回归检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
```

检查使用合成记录和隔离测试窗口；部分音频检查会短暂播放声音，界面检查需要可交互的 Windows 桌面会话。测试通过不等于所有桌面端版本或真实使用场景均已验证。

高级启动参数：`--paused` 暂停启动；`--codex-home <目录>` 指向另一份本机记录目录；`--thread <聊天ID>` 指定初始聊天范围。日常多选请使用设置界面。
